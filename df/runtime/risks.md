# The Factory Risks and Blockers

| ID | Risk/blocker | Severity | Owner | Status | Mitigation |
|---|---|---|---|---|---|
| R-REB-001 | Browser-captured remote assets may be unavailable, volatile, blocked, or not licensed for repository/runtime use. | High | designer/devops | Open | Capture through Selenium into manifests, record license/source metadata, and mark unavailable/disallowed resources as blockers instead of silently embedding them. |
| R-REB-002 | Seed reset can delete non-demo data if path/resource/environment guards are insufficient. | Critical | data-engineer | Open | Reset only deterministic TUT/demo records, require explicit confirmation flag, refuse production/unknown environments by default, and record before/after counts. |
| R-REB-003 | Full frontend reimplementation can start before component/template contracts stabilize, causing large rework. | High | sa/frontend-dev | Open | Enforce dependencies: design normalization and contract generation precede frontend renderer/template work. |
| R-REB-004 | Moving to Selenium may reduce existing automation coverage if Playwright is removed too early. | Medium | devops/qa | Open | Retain Playwright until Selenium suites pass and PO accepts replacement coverage. |
| R-REB-005 | The 406-component inventory is too large for a single frontend task. | High | sa/frontend-dev | Open | Implement contracts and renderers by grouped/prioritized component batches; keep each delivery task single-lane and evidence-based. |
| R-DFCA-001 | GitHub Copilot Cloud Agent task API is public preview and may change endpoint, headers, request schema, or response schema. | High | devops | Open | Isolate all REST calls in one client layer, document exact verified API version/headers, provide dry-run/mock tests, and keep manual/local adapters as rollback. |
| R-DFCA-002 | Cloud-agent token permissions or logs could expose repository secrets if not handled carefully. | Critical | devops | Open | Use environment-only credentials, document least-privilege permissions, redact authorization/token values from all logs/artifacts, and add tests for redaction. |

| R-REB-19-001 | Publishing from the page editor changes node status without triggering replication, so authors see "Published" while the publish environment serves the page with zero components. | Critical | sa/backend-dev | **Closed 2026-08-19** (`BUG-PUBLISH-REPLICATION`) | Trigger replication from the status transition in the service layer so every publish path behaves identically; until then publish through `POST /api/author/content/bulk/publish` or `scripts/publish_tut_usa_site.py`. | R-REB-19-002 | The editor renders array, object, and asset fields as plain text inputs, so editing one persists a string in place of structured content (265 array + 66 object + 91 asset fields across the 406 active components). | High | sa/frontend-dev | **Partially closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Add list/object editors and a DAM picker driven by the registry `x-asset` marker; until then author those fields through the API. The richer authoring UX and the DAM picker (`B-2`) remain open design work. |
| R-REB-19-003 | Editor saves never persist component order, additions, or deletions — `handleSave()` only PUTs properties for components that already have a `nodePath`. | High | frontend-dev | Open | Extend the save path to create, delete, and write `orderIndex` (the backend already orders children by it). Evidence: `df/artifacts/REB-19/devops/blockers.md` B-3. |
| R-REB-19-004 | `ContentNodeRepository.deleteSubtree` is a native DELETE `@Query` without `@Modifying`, so every content deletion through the author API returns HTTP 500 and test fixtures accumulate permanently in the shared content tree. | High | backend-dev | **Closed 2026-08-19** (`BUG-CONTENT-DELETE`) | Add `@Modifying` and cover it with a repository test that deletes a node with descendants. | R-INFRA-001 | Every `*IT` integration test is unrunnable on Docker Engine 29+ (Testcontainers 1.19.8 negotiation returns HTTP 400) **and** no build stage executes `*IT` at all, so integration coverage silently does not gate. A pre-existing `deleteSubtree` IT would otherwise have caught `BUG-CONTENT-DELETE`. | High | devops | **Closed 2026-08-22** (`INFRA-TESTCONTAINERS-DOCKER29`) | Pin removed in favour of the Boot-managed Testcontainers 2.0.5 line; failsafe bound to `verify` with `**/*IT.java`. Evidence: `df/artifacts/INFRA-TESTCONTAINERS-DOCKER29/devops/summary.md`. |
| R-REB-26-001 | Deleting a published page never removes it from the publish environment: `ContentNodeService.delete()` only calls `nodeRepository.deleteSubtree()` plus an audit entry, and **no producer anywhere emits `ReplicationAction.DELETE`** even though `ReplicationReceiver` already implements `case DELETE -> deleteContent(event)`. An author deletes a page and `:8081` keeps serving it indefinitely. | Critical | sa/backend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Emit a DELETE replication event from the delete path (the receiving half already exists); `sa` to confirm delete-on-publish vs. unpublish-then-delete semantics. Re-confirmed live by REB-26 `S4` on 2026-08-21. Evidence: `df/artifacts/REB-26/devops/blockers.md` R26-1. **Fixed 2026-08-23:** `delete()` publishes `ContentDeletedEvent`; a new listener calls `ReplicationAgent.replicateDelete()` (the existing `replicate()` resolves the node first and cannot serve a deletion). Verified live end to end, and REB-26 `S4` now reports the publish environment no longer serving the deleted page. |
| R-REB-26-002 | Unpublishing does not stop delivery either: `ReplicationReceiver.deactivateContent()` flips only the page node's status to `DRAFT` and leaves its child components in place, and the publish delivery API serves pages regardless of status. No supported API can retract published content. | High | sa/backend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Replicate the whole subtree on deactivate and make the publish resolver status-aware; `sa` to decide whether publish delivery filters on status. Evidence: `df/artifacts/REB-26/devops/blockers.md` R26-2. **Fixed 2026-08-23:** `deactivateContent()` walks the subtree and publish-instance delivery filters on `PUBLISHED`, gated on `flexcms.runmode` so the author still serves drafts. Verified by REB-20 `S9` and REB-26 `S4`. |
| R-REB-26-003 | Numeric property fields cannot be cleared and clear-then-retype silently corrupts the value: `PropertyField()` uses `value={Number(value ?? 0)}` with `onChange={Number(e.target.value)}`, so emptying a field snaps to `0` and retyping lands the digits beside it (`42` → clear → type `1004` yields `10040`). 71 numeric fields affected. | High | frontend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Keep the raw string in component state and coerce on save so an empty field stays empty. Suite works around it via `EditorAuthoringPage.clearAndType()`. Evidence: `df/artifacts/REB-26/devops/blockers.md` R26-3. **Fixed 2026-08-23:** the number branch keeps the raw keystrokes in state and coerces on change, so an emptied field stays empty and retyping no longer concatenates onto a re-inserted 0. Exercised across the 71 numeric fields in the REB-26 sweep. |
| R-REB-26-004 | The reference site renders interactive components as read-only field previews: it has 14 group renderers plus a default, not 406 component renderers. **42 of 42 form/data-capture components render no interactive control**, 9 image-like asset fields produce no `<img>`, and 18 of 30 reference fields produce no anchor. Authoring and delivery are correct; only the sample site understates the platform. | Medium | sa/frontend-dev | Open | Add component-level renderers for the interactive categories; `sa` to decide how far the reference site is meant to go (may be later-task scope rather than a REB-09 defect). Evidence: `df/artifacts/REB-26/devops/blockers.md` R26-4. |
| R-REB-20-001 | Moving content leaves the moved node's `parentPath` stale: `ContentNodeService.move()` computes `updatedParent` as `n.getParentPath().replace(sourcePath, newPath)`, which is a no-op for the subtree's own root because that node's parentPath does not contain sourcePath. The page then vanishes from its new parent's `/children` listing and lingers in its old parent's, so the admin content tree shows it in the folder it was moved out of. `bulkMove()` delegates to `move()`, so single and bulk moves are both affected. | High | sa/backend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Set the subtree root's parentPath to targetParentPath explicitly; cover with a service/repository test that moves a node **with** descendants and asserts both the root's and a descendant's parentPath. Evidence: `df/artifacts/REB-20/devops/blockers.md` R20-1. **Fixed 2026-08-23:** `move()` re-parents the subtree root explicitly; unit test `move_reparentsTheMovedNodeItself_notJustItsDescendants` added; REB-20 `S6` PASS. |
| R-REB-20-002 | A content node that has ever carried a workflow can never be deleted: `workflow_instances.content_node_id` references `content_nodes.id` with no `ON DELETE` rule, so `deleteSubtree` violates the FK and the author API answers an opaque HTTP 500. Cancelling does not help — cancelled and completed instances keep the reference — so any page that went through review is permanently undeletable. | High | sa/backend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Decide the intended semantics (cascade the workflow history, null the reference, or refuse with a clear 409 naming workflow history) and stop surfacing it as a generic 500. Evidence: `df/artifacts/REB-20/devops/blockers.md` R20-2. **Fixed 2026-08-23:** migration `V19` adds `ON DELETE CASCADE`; verified `confdeltype='c'`; REB-20 `S12` PASS. |
| R-REB-20-003 | Scheduled publish never updates the author-side status: `ScheduledPublishingService.processScheduledPublishes()` calls `replicationAgent.replicate(..., ACTIVATE, ...)` and `clearScheduledPublish(node)` directly, bypassing the status transition that `POST /node/status` and `bulk/publish` both perform. The public is served a page the author still shows as DRAFT, and `findDueForPublish` (status <> PUBLISHED) would re-select it. | High | backend-dev | **Closed 2026-08-23** (`BLOCKER-REMEDIATION-2026-08-23`) | Route scheduled publishing through the same status transition as the other publish paths so all three behave identically.
