# BUG-009 — Workflow `for-user` inbox ignores `userId`

|---|---|

| Severity | Medium |

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. `GET /api/author/workflow/for-user?userId=X`

**Expected:** Only the workflow tasks that X can act on.

**Actual:** Every ACTIVE workflow instance.

## Root cause

`WorkflowEngine.java:173-174`: `listForUser(userId, ...)` returns `instanceRepo.findByStatus(WorkflowStatus.ACTIVE, pageable)`.

## Acceptance criteria

- [ ] AC1: The inbox returns only the instances whose current step X can act on, following the assignment rule defined in refinement: direct assignee, and/or group/role membership.
- [ ] AC2: Unknown users get an empty page, not an error.
- [ ] AC3: A regression test reproduces the bug. It fails before the fix and passes after it.

## Refinement needed

Define what "can act on" means with today's data model: step assignee, role, or group. Align with ECMS-48 (Workflow engine v2), which may replace this endpoint. If the rule is a product decision, ask it under **Questions** and move the task to Blocked.
