# BUG-011 — Trailing slash on the XF endpoint gives a misleading 404 message

| Field | Value |
|---|---|
| Type | Bug |
| Priority | P3 |
| Severity | Cosmetic |
| Area | `flexcms-author` ExperienceFragmentController |
| Original IDs | XF-039 |
| Depends on | — |

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. `GET /api/author/xf/?siteId=tut-usa` (note the trailing slash)

**Expected:** Either the list is returned, as without the slash, or a 404 whose detail names the unmatched path.

**Actual:** 404 "Experience Fragment not found: content.", because the empty segment is bound to `{xfPath}`.

## Root cause

The empty path segment matches the `{xfPath}` mapping in `ExperienceFragmentController`.

## Acceptance criteria

- [ ] AC1: A request with a trailing slash behaves exactly like the same request without it, or returns a 404 whose detail does not mention a fragment path.
