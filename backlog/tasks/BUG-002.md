# BUG-002 — Workflow approve/reject shows success when the API call fails

| Field | Value |
|---|---|
| Type | Bug |
| Priority | P1 |
| Severity | Major |
| Area | Admin UI `/workflows` |
| Original IDs | WF-013, GAP-109 |
| Depends on | — |

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. Open `/workflows` with an active task.
2. Make the approve (or reject) request fail, e.g. stop the backend or return 500.
3. Click **Approve**.

**Expected:** An error message is shown, and the task keeps its previous status.

**Actual:** The task is shown as approved/rejected anyway.

## Root cause

`frontend/apps/admin/src/app/(admin)/workflows/page.tsx:596-612`: `handleApprove`/`handleReject` send the request and then call `setTasks(...)` immediately. They never check `r.ok` and never roll back.

## Acceptance criteria

- [ ] AC1: The task status in the UI changes only after the API responds with 2xx.
- [ ] AC2: On a non-2xx response or network error, an error message (with the problem `detail` when present) is shown and the row is unchanged.
- [ ] AC3: A regression test reproduces the bug. It fails before the fix and passes after it.
