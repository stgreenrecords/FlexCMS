# BUG-013 — DAM browser loads at most 200 assets and never pages

## Reproduce

1. Have more than 200 assets in a site.
2. Open `/dam`.

**Expected:** All assets are reachable through paging or infinite scroll, and search covers all of them.

**Actual:** Only the first 200 are fetched (`/api/author/assets?size=200`). The grid, tree and client-side search silently omit the rest. With 182 seeded assets it is latent today.

## Root cause

`frontend/apps/admin/src/app/(admin)/dam/page.tsx:591` fetches one page of 200 and never requests more.

## Acceptance criteria

- [ ] AC1: The DAM browser pages through the assets API (paging controls or load-more), so every asset is reachable.
- [ ] AC2: Search is performed server-side, or across all pages, not only the loaded page.
- [ ] AC3: A regression test reproduces the bug. It fails before the fix and passes after it.
