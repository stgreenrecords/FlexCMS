# BUG-008 — Unsupported HTTP methods return 500, and site admin endpoints return JPA entities

| Field | Value |
|---|---|
| Type | Bug |

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. `curl -X DELETE http://localhost:8080/api/admin/sites/qa-dupe-test`

**Expected:** `405 Method Not Allowed` as RFC 7807 problem+json with an `Allow` header, because deleting sites is not implemented.

**Actual:** 500. The report shows `LazyInitializationException ... Site.domains (no session)`.

## Root cause

`SiteAdminController` has no `@DeleteMapping`, and `GlobalExceptionHandler` has no handler for `HttpRequestMethodNotSupportedException`, so the request falls through to the `Exception` catch-all. Separately, `createSite` returns a `Site` and `addDomain` returns a `DomainMapping` entity; with `open-in-view: false`, serializing lazy associations throws `LazyInitializationException`.

## Acceptance criteria

- [ ] AC1: Any unsupported method on any endpoint returns 405 problem+json (with an `Allow` header) instead of 500.
- [ ] AC2: Every `SiteAdminController` endpoint returns DTOs, never JPA entities, and no response can trigger `LazyInitializationException`.
- [ ] AC3: Deleting a site stays out of scope. If it is wanted, file it as a FEAT task.
- [ ] AC4: A regression test reproduces the bug. It fails before the fix and passes after it.
