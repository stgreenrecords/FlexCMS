# BUG-004 — Experience Fragments page is stuck on the first listed site and has no site switcher

| Field | Value |
|---|---|
| Type | Bug |
| Priority | P2 |
| Severity | Major |
| Area | Admin UI `/experience-fragments` |

| Depends on | — |

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. Open `/experience-fragments` in a fresh session.

**Expected:** The user sees fragments of a site they choose. The seeded tut-usa fragments are reachable.

**Actual:** The page calls `xf?siteId=tut-gb` (the first site the API lists) and shows "No fragments found". There is no way to switch sites.

## Root cause

`frontend/apps/admin/src/app/(admin)/experience-fragments/page.tsx:117`: `const site = sites[0];`, and there is no selector.

## Acceptance criteria

- [ ] AC1: The page has a site selector listing every site from `GET /api/admin/sites`, built with the same `@flexcms/ui` select pattern other admin pages use.
- [ ] AC2: Selecting a site loads that site's fragments. The selection survives a reload (URL query parameter `site`).
- [ ] AC3: Without a `site` parameter, the first site in the list is selected, and the selector shows it.
- [ ] AC4: A regression test reproduces the bug. It fails before the fix and passes after it.
