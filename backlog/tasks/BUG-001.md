# BUG-001 — PIM Import Wizard target-catalog dropdown is always empty

|---|---|

> Status is tracked only in [`backlog/BOARD.md`](../BOARD.md).

## Reproduce

1. Open `http://localhost:3000/pim/import`.
2. Open the **Target Catalog** dropdown.

**Expected:** The seeded catalog ("TUT 2026 Model Lineup") is listed.

**Actual:** Only the placeholder is shown. The page calls `GET :3000/api/pim/v1/catalogs?size=100`, which returns 404 because there is no Next.js rewrite; the same call on `:8080` returns 200. The whole import wizard is blocked.

## Root cause

`frontend/apps/admin/src/app/(admin)/pim/import/page.tsx:53` uses the relative `API_BASE = '/api/pim/v1'`; `/pim/page.tsx:133` already uses the absolute backend base URL.

## Acceptance criteria

- [ ] AC1: The Import Wizard lists every catalog returned by `GET /api/pim/v1/catalogs` on the Author API, and the import can proceed to the next step.
- [ ] AC2: The PIM API base URL comes from the same shared configuration the other PIM pages use (no duplicated constant).
- [ ] AC3: A regression test reproduces the bug. It fails before the fix and passes after it.
